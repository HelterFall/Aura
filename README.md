# Aura

**Aura** — Android-приложение для исследования и извлечения ресурсов из архивов визуальных новелл.

Проект развивается как модульный просмотрщик: каждый формат архива и каждый декодер ресурса будут отдельными компонентами. Цель первого этапа — надёжная файловая основа, затем поддержка Nitroplus (NPA/NPK и варианты контейнеров), после этого — другие движки и форматы.

## Текущий статус

- [x] Android-проект на Kotlin + Jetpack Compose.
- [x] Выбор папки игры через Storage Access Framework.
- [x] Просмотр файлов и каталогов первого уровня.
- [x] Предварительное определение кандидатов на архив по расширению.
- [x] GitHub Actions для сборки debug APK и публикации APK как артефакта.
- [ ] Определение форматов по сигнатурам и структуре.
- [ ] Чтение и извлечение NPA.
- [ ] Чтение и извлечение NPK2.
- [ ] Просмотр изображений и других ресурсов.
- [ ] Дополнительные движки (например, KiriKiri/XP3).

> На текущем этапе приложение только показывает файлы и отмечает возможные архивы по расширению. Оно пока не расшифровывает и не распаковывает игровые контейнеры.

## Сборка

Требования:
- JDK 17
- Android SDK с Android SDK Platform 35
- Gradle 8.9 (в CI устанавливается автоматически)

Локально:

```bash
gradle :app:assembleDebug
```

APK появится здесь:

```
app/build/outputs/apk/debug/app-debug.apk
```

## GitHub Actions

Workflow `.github/workflows/android-apk.yml` запускается при push в `main`, pull request и вручную через **Actions → Android APK → Run workflow**.

После успешной сборки скачай артефакт **Aura-debug-apk** из страницы запуска workflow. Это debug APK для тестирования, не подписанный релизный APK для публикации в Google Play.

## Архитектура

- `app` — Android UI и интеграция с файловой системой Android.
- `core/archive` — модели форматов и обнаружение архивов.
- `formats` — отдельные реализации игровых контейнеров (будут добавляться).
- `codecs` — декодеры изображений, аудио и алгоритмов сжатия (будут добавляться).

## Принципы

1. Не доверять одному только расширению файла: окончательное определение должно учитывать сигнатуру и структуру контейнера.
2. Не загружать целиком большие архивы в память без необходимости.
3. Читать содержимое потоково, проверять смещения и размеры до выделения памяти.
4. Разделять обнаружение формата, чтение индекса, декодирование и экспорт.
5. Не включать в репозиторий игровые архивы, извлечённые ресурсы или ключи.
